## Objective

Turn supported Claude Code hook and optional status snapshots into bounded
provider observations for Pacium-launched Claude terminals without changing
Claude decisions, terminal lifecycle, user settings files, or custom status
lines.

## Existing behavior

- Protocol 19 carries a strict provider snapshot and the Activity inspector
  consumes explicit provider evidence.
- Claude sessions start with unavailable health, unknown capabilities, no
  provider attention, and no provider activity.
- Launch presets contain fixed executable/argv but PTY creation has no
  session-scoped environment extension.
- The HTTP server has no provider-ingestion route.
- The installed local evidence is Claude Code `2.1.206`; supported versions
  must still be capability-tested rather than inferred from this machine.

## Proposed behavior

Before a Claude PTY starts, the server registers a session with a
process-local observer, creates a 256-bit hook token, and appends one fixed
`--settings` JSON value containing observation-only HTTP hooks. The token and
URL enter only that PTY environment and hook header interpolation. Valid hooks
update the session snapshot and broadcast an ordinary `session.updated`.

The observer also accepts strict status JSON at a separate authenticated path.
It emits usage/version activity only when explicitly connected; Pacium does not
set `statusLine` because Claude supports only one configured command and
overwriting it would be destructive.

## Architecture and boundaries

### Modules touched

- `packages/contracts/src/provider-observation.ts`: typed Claude status/usage
  extension fields.
- `packages/contracts/src/protocol.ts`: protocol 20.
- `apps/local-server/src/claude-observer.ts`: registration, fixed settings,
  strict normalization, deduplication, snapshot reduction, version detection.
- `apps/local-server/src/pty-adapter.ts`: server-owned per-session environment
  additions only.
- `apps/local-server/src/session-manager.ts`: prepare/release observer and apply
  validated snapshot updates.
- `apps/local-server/src/http-server.ts`: exact hook/status ingress boundary.
- Existing web attention/activity consumers require no new authority.

### Data/state changes

- Entity/schema changes: Claude activity extension gains nullable bounded
  status fields.
- Commands/events: no browser command; HTTP provider ingress is server-to-local
  CLI only.
- Idempotency: bounded event fingerprint set per session.
- Migration: no file migration; snapshots remain process-local.

### Protocol changes

- Increment protocol 19 to 20.
- Add only typed nullable Claude status/usage scalars; no arbitrary provider
  object.

### Authorization and privilege

- One random token per registered Claude session.
- Exact loopback Host, no Origin, exact UUID path, POST and JSON only.
- Provider ingestion never accepts the browser access token and is not exposed
  through WebSocket messages.
- Hook settings are fixed JSON generated by the server, not a shell endpoint.

## Failure model

| Failure point                                   | Expected state                                           | Recovery                               |
| ----------------------------------------------- | -------------------------------------------------------- | -------------------------------------- |
| Version command unavailable/invalid             | Provider version remains unavailable; launch still works | Hook/status evidence may still connect |
| Hook settings blocked by managed/user allowlist | Observer remains unavailable or becomes stale; PTY works | Operator adjusts trusted Claude policy |
| Hook endpoint unreachable/timeout               | Claude continues; no false observation                   | Next hook retries naturally            |
| Invalid token/session/path                      | Request rejected without state change                    | Current registered hook retries        |
| Malformed/oversized payload                     | Request rejected and bounded diagnostic health           | Next valid event restores ready health |
| Duplicate delivery                              | No second activity or attention transition               | Later unique event proceeds            |
| Observer released/session closed                | Token becomes invalid                                    | Relaunch creates a new session/token   |
| Status not configured                           | Usage capability stays unknown                           | Optional operator companion later      |

## Compatibility

- Supported versions: capability-detected; local fixture version 2.1.206 is
  recorded, not treated as a universal range.
- Fallback behavior: direct PTY and process attention remain active.
- Rollback: remove observer injection and protocol-20 typed fields together.

## Test plan

- Unit: schemas, mappings, version parsing, settings exactness, token
  separation, dedupe, cap/freshness/health transitions.
- Property/fault: unknown keys/events, deep/large JSON, duplicate IDs,
  timestamp order, replay and released tokens.
- Contract: protocol 20 and Claude extension cross-provider rejection.
- Integration: hook/status HTTP authorization and `session.updated`.
- Browser: existing Activity rendering receives Claude provider facts without
  new actions; full suite for terminal independence.
- Security: no prompt/tool/transcript/env/token retention, no decision output,
  exact loopback authority.
- Performance: fixed 64 KiB ingress, 32 activities, and bounded fingerprint
  history; no polling.
