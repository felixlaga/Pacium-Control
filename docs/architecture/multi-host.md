# Multi-host direction

Multi-host operation is deferred and is not part of the active roadmap.

The local-first product must first prove:

- excellent direct PTY behavior;
- multi-session UX;
- useful agent attention;
- Git inspection;
- Pacium mode;
- sustained personal use.

Any future multi-host proposal must define:

- authentication and authorization;
- privilege separation;
- remote terminal encryption;
- host trust and enrollment;
- process and session ownership;
- disconnect and unknown-outcome semantics;
- state synchronization;
- migration from local-only profiles;
- explicit opt-in and rollback.

The old host-agent and tailnet blueprint is historical context, not implementation authority.
